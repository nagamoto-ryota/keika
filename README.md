# ケイカ

話すだけで支援経過。運営指導の備えは、そのついでに。

ケアマネジャーが話した内容を支援経過の文章に整え、事業所の書類フォルダと突き合わせて、確かめておきたいことを先回りで知らせるアプリです。Built with Claude: Japan 2026 の提出作品として制作中です。書類フォルダは、Google ドライブの同期フォルダでも、PC の普通のフォルダでも使えます。Google のアカウントや API 連携は要りません。

> 指摘はすべて「確認してください」という形のお知らせです。法的助言や監査の代わりではなく、最終判断は事業所と保険者にあります。

## 触ってみる（API キー不要）

同梱の結果（架空データ）をそのまま見られます。Claude は呼びません。

```
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe -e ".[dev]"
.venv/Scripts/python.exe -m keika.cli serve --sample
```

http://127.0.0.1:8000 を開きます。

## 架空データで Claude を動かす

アプリのフォルダに `.env` というファイルを作り、`ANTHROPIC_API_KEY=自分のキー` の1行を書きます。`.env` はリポジトリに入りません。
書類のフォルダは `KEIKA_DRIVE_ROOT` で指定します（中に `利用者/`、`事業所/`、`入口/` を置きます）。Google ドライブの同期フォルダでも、PC の普通のフォルダでも構いません。社内の共有フォルダは未確認です。指定しなければ同梱の架空データを読みます。データベースの場所は `KEIKA_DB_PATH` で、同期フォルダの外に置きます。

```
.venv/Scripts/python.exe -m keika.cli sync     # 書類を読み取り、支援経過の CSV を取り込む
.venv/Scripts/python.exe -m keika.cli serve    # 画面を開き、入口のフォルダを見張る
```

`KEIKA_AS_OF=2026-11-04` を指定すると、画面に「デモ基準日」と出て、その日を今日として動きます。記入日時は常に実際の時計です。

## 開くと終わっている入口

ケアマネが毎日の点検票を読まなくて済むように、先に記録を済ませ、聞く事だけを出します。

- 先頭は「前回開いた後の N件を記録しました」です。記録は未確認の下書きで、最後に決めるのは人です。未確認の数は小さく常に出します。
- 聞く事は1日5件までです。超えた分は「あと N件」と出し、「すべての項目」で見られます。1件は記録の確認か、下書き1通です。
- 点検の項目は毎日の画面から外し、その人のページ、訪問前の1枚、「すべての項目」（`/todo`）に置きます。点検の結果と数は変えていません。各項目には、根拠の書類、日付、語句を機械で1行添えます。特定できない物は、そう書きます。
- 期限の近い物だけ、ケイカの一言として先頭に出します。
- 下書きの画面は、先頭に何をするかの1行と残りの数だけを出します。「〇〇」の欄は本文の表の中で赤く示し、その場で書き込めます。答えは書かれたまま入れ、AI を呼びません。空いたままでも Word で保存でき、〇〇 と印はそのまま残ります。
- 下書きの印が付いた文は、Claude が話と照らします。発言どおりなら黄色にしません。確かめる文は本文の中で黄色になり、押すとその場で直せて、元の発言と〔いいよ〕〔違う〕が出ます。ただし薬の話は発言どおりでも消さず、黄色に「薬・未確認」を付けたまま残し、人が〔見た〕を押すまで残りの数に入れます。誤って通す率は、正解のあるデータが無いので測っていません。

## AI相談（左に実物、右に会話）

「この人どう対応するのが良いと思う？」と聞くと、その人の記録と書類を読んで答え、根拠の箇所を左で光らせます。

- 枠は利用者ごとに1本で、会話は残ります。答えを作っている間に別の人へ移れます。同時に作るのは3本までです。「全体」の枠で読めるのは、名前の一覧だけです。
- 読む口はサーバーがその枠の人に固定しています。道具に利用者を選ばせないので、別の人の記録や書類は Claude に渡りません。
- 別の人の名前が話に出たら、AI を呼ぶ前に移るかを聞きます。台帳の字と読みで照らすので、誤変換までは見つけられません。
- 答えは結論と次の一手を先に出し、根拠は畳みます。「もっと詳しく」と言えば詳しく答えます。
- 「交付ってどれのこと？」と聞けば、該当の書類を左に開きます。項目の〔ケイカに聞く〕から移ると、質問が入力欄に入ります（送るのは人です）。
- 頼まれた時だけ、次の手順の案、ケアプランの下書き、メールの下書きを作り、左に実物で開きます。AI相談で作ったメールは下書きまでです。
- 答えは記録に自動で入りません。〔記録の入力欄へ送る〕を押した時だけ入力欄に入り、そのあとは普通の記録と同じ検査を通ります。

**線:** 引用は原文と機械で照らし、無ければ差し戻します。薬の中止や変更、診断、受診の要否、急ぐ度合いの判断、事業者の推奨は、答えを見せる前に語句で検査し、当たれば1回だけ書き直しを頼み、だめなら決まった文を出します。

**機械で保証できない事:** ケイカの答えの全文を機械で保証はできません。確かめられるのは引用と決まった語句だけで、引用の無い文が正しいかは確かめられません。書類に無い一般の知識も答える事があり（「一般には」と分けるよう指示しています）、その正しさも確かめていません。人が読んで判断してください。

**確かめた範囲:** 意地悪な質問（`tools/desk_check.py`、架空データ、19件）で、機械の判定は NG 0 件でした。書き手が用意した質問で、件数も少なく、線を越えない保証ではありません。

**費用（Sonnet 5.5、架空データの実測）:** 記録を読む最初の1往復が約 $0.05〜0.07、同じ枠の続きは少なくなります。意地悪な質問 19件の通しが $0.4665 でした。ケアプランの下書きは1回 $0.2564 と会話 $0.0389（71秒）です。下書きの印の照合は Opus で 8文 約 $0.02 です。モデルは `KEIKA_MODEL_DESK` で変えられます。

## メールの案、共有、送ったメールを支援経過へ

- **先回りの案:** 話から入った記録を、連絡に関わる語がある物だけ Claude が読み、担当の他事業所へのメールが要りそうなら案を1通作ります。入口に「〇〇さん: △△への照会メールの案を用意しました」と根拠の1行つきで出ます。1つの記録を考えるのは1回だけで、同じ相手への案が開いている間は重ねません。
- **共有:** 記録の〔共有〕から相手を選ぶと、その相手向けの短い文を作ります。既定は担当の他事業所で、家族と医療機関も選べます。他事業所は業務の要点、家族はやさしい言い方、医療機関は事実と経過だけです。
- **宛先:** その利用者に登録された相手だけです。自由入力はありません。
- **画面:** 先頭の1行は「確かめて、メールアプリで開く」です。本文は行ごとにその場で直せ、確かめる行（〇〇、薬の文、判断に読める文）は赤くなります。赤い行が残る間は主ボタンを押せず、理由がボタンの横に出ます。脇の操作は〔AIに直してもらう〕と〔要らない〕だけです。
- **送信:** 自動では送りません。人が主ボタン〔メールアプリで開く〕を押した時だけ動き、処理は `send_mail` の1か所です。押すと控えに残り、メールアプリ（mailto:）が開きます。このアプリからメールは出ません。パスワードや認証情報は扱いません。
- **Gmail の下書き:** Gmail とつないであれば、主ボタンは〔Gmailの下書きに入れる〕になり、押すと Gmail の下書きに1通入ります。送るのは Gmail から人が行います。求める権限は、下書きを作るための `gmail.compose` と、ケイカが作ったメールが送信済みかとその返事を読むための `gmail.readonly`（変更・送信・削除はできない範囲）の2つです。`gmail.compose` は Google の決まりでは送信もできる範囲ですが（下書きだけに絞った範囲はありません）、ケイカは送信の処理を持たず、送るのは人です。つなぐには、Google Cloud で作った OAuth クライアント（デスクトップ アプリ）の JSON を DB と同じフォルダに `gmail_client.json` の名前で置き、`python -m keika.cli gmail-connect` を実行してブラウザで同意します。token はそのフォルダの `gmail_token.json` に入ります（どちらも git に入らない `data/` の中）。本文を URL に載せることはしません。つないでいない時は「Gmail はまだつながっていません」と出て、主ボタンは〔メールアプリで開く〕のままです。
- **添付:** Gmail につないである時だけ、メール案の画面に「添付」の欄が出ます。候補はその利用者の書類（読み取りフォルダの物）と、ケイカで作った下書き・ケアプラン（Word にして付けます）だけで、他の人の書類は候補に出ず、画面から送られてきても使いません。AI の案が本文で触れている書類は最初から選んでありますが、決めるのは人です。本文に「添付」とあるのに何も選んでいない時、選んだのに本文に無い時、合計が 25MB を超える時は、赤く出して主ボタンを押せません。付けた物の名前は、下の支援経過の案にも入ります。つないでいない時は「添付は Gmail につないだ時だけ使えます」と出ます（メールアプリへの受け渡しでは添付できないため）。
- **送ったメールと受け取った返事を支援経過の案に（設定が要ります）:** Gmail につなぐと、入口を開いた時に（1分に1回まで）次の2つを確かめ、入口の確認カードに支援経過の案を出します。〔いいよ〕で支援経過に入り、〔違う〕で直せます。記録に自動では入りません。
  - 送ったメール: ケイカが下書きに入れたメールが Gmail から実際に送られたか。見るのはそのスレッドの各メールの番号と目印（送信済みか）と日時だけです。下書きのまま・消した下書きは案になりません。文は「11/6 〇〇さんへ、メールで照会した（件名「…」）。添付: …」の決まった形で、AI の費用はかかりません。
  - 受け取った返事: そのスレッドに相手から届いた返事だけを読みます。前のメールの引用は切ってから、AI（Sonnet 5.5）が要点を短くまとめます（「11/6 〇〇さんから返信。…」、添付は書類の名前だけ）。病名の推測や受診・薬の判断に読める要約は使わず、「元のメールで確かめてください」にします。費用は返事1通あたり約 $0.002 です（架空の返事1通の実測、3.4秒）。
  - ケイカが作っていないメール、別のスレッドのメールは読みません。求める権限は `gmail.compose` と `gmail.readonly` の2つで、前の権限でつないだ人は `gmail-connect` でつなぎ直すまで、この確認は動きません。
- **送る前の機械の検査:** 宛名と宛先、利用者の氏名、別の利用者の名前、〇〇 の残り、薬や受診の判断や急ぐ言い方を毎回確かめ、当たれば主ボタンを押せません。薬の話が入っていれば、人が確かめるまで止めます。家族宛てで本人の同意が要りそうな語があれば、止めずに一言知らせます。これは語句の検査なので、文の正しさの保証ではありません。読んで決めるのは人です。
- **費用（Sonnet 5.5、架空データの実測）:** 案や共有の文は1通 約 $0.01 です。

## 録音の文字起こしから書類の下書きを作る

録音機の文字起こし（文字、字幕の形式、Word、文字の入った PDF）を `入口/` に置くと、支援経過に加えて、担当者会議の要点かモニタリングの記録の下書きができます。音声ファイルそのものは読みません。見本は `sample_data/demo_talks/` にあります。

下書きは文ごとに元の発言を開けます。確かめられない文には印が付き、話に無い欄は「〇〇」のままです。清書と確定は人が行います。

## 指摘から次の手順と文の下書きを作る

指摘カードには、支援経過の文を先回りで作らず、メールで済む指摘にだけ次の一手を1文で出します（例「会議の開催を調整しませんか。するなら、担当の事業所と主治医に、意見照会と日程調整のメールを作ります」）。〔作って〕を押すと、その人の台帳にある相手（提案に書いた相手だけ）に1通ずつメール案を作り、メール案の画面へ進みます。そこから Gmail の下書きに入れ、人が送ると、送ったメールと返事が支援経過の案になります。〔今はいい〕で提案を閉じます。提案の文は決まった形なので費用はかからず、メール案は架空データの5通で 21秒・$0.024 でした。メールで済まない指摘は〔確認した・問題なし〕だけです。前からの「次の手順と下書きを作る」と「今日の日付で経緯を残す」は「その他」の中にあります。

## 訪問の前に1枚で確かめる

利用者のページの「帳票」の欄から「訪問前の1枚」を開くと、前回からの流れ、宿題、今確かめること、目標が並びます。ここまでは保存済みの記録と点検の結果を並べるだけで、Claude を呼びません。

「聞くことを洗い出す」を押すと、Claude が書類を読み、アセスメントで聞けていない項目（国の23項目）を挙げます。要支援の人には、現状に対する意向、基本情報、基本チェックリストの25問も出します。前回の答えは、書類の原文で確かめられた物だけを添えます。

印刷して手で書く、文章をコピーして別の所に書く、その画面で直接入力する、のどれでも使えます。直接入力した内容は自動で保存し、「記録の入力欄へ送る」で記録の下書きに進めます。AI が整えた文を確かめて決めるのは人です。

## ケアプランの下書きを作る

利用者のページの「帳票」の欄にある〔下書きを作る〕を押すと、Claude が書類と記録を読み、居宅サービス計画書の第1〜3表の案を作ります。要支援の人は介護予防サービス・支援計画書の形にします。

様式の表のまま、どのマスもその場で打って直せます。自動で保存し、直す前と後の文を変更の履歴に残します。もう一度作ると別の下書きになり、人の手直しは上書きしません。Word はマスを結合しない表で保存します。「事業所のフォルダの出力先に置く」は、読み取りフォルダの中の `ケイカの出力` に新しい名前で置きます。点検の対象の外で、今ある書類は変えません。表の崩れは Microsoft Word と LibreOffice で PDF にして確かめました（架空データ）。Google ドキュメントで開いた時の見え方は未確認です。

- 文ごとに元の書類を開けます。元の文を原文と機械で照らし、確かめられない文には印を付けます。
- 本人と家族の意向は、書類の言葉をそのまま使います。頻度、期間、事業所は読み取れなければ「〇〇」のままです。
- 医療の判断と、事業所や商品を勧める文は入れません。
- 「アセスメントと読み比べる」を押すと、下書きとアセスメントの食い違いを原文つきで出します。点検の項目には手を入れていません。
- AI の案です。確定は人が行います。説明、同意、交付はこの画面では扱いません。

## アセスメントの下書きを作る

利用者のページの「帳票」の欄の「アセスメント」にある〔下書きを作る〕か、AI相談で「アセスメントの下書きを作って」と頼むと、ケアプランの下書きと同じ作りで、アセスメントの案を作ります。今のアセスメントの書類がある人は〔今の書類を見る〕で左に実物が開くのも、今までどおりです。

- 項目は国の課題分析標準項目（基本情報に関する項目 9、課題分析（アセスメント）に関する項目 14、計 23 項目）です。項目名と各項目の「主な内容（例）」は、厚生労働省「「介護サービス計画書の様式及び課題分析標準項目の提示について」の一部改正について」（令和5年10月16日 老認発1016第1号、介護保険最新情報 Vol.1178）の改正後の原文で確かめた物だけを使っています。
- 表のまま各マスをその場で直せ、自動で保存し、変更の履歴を残します。もう一度作ると別の下書きです。Word で保存できます。
- 文ごとに元の書類や記録に戻れます。書類と記録に無い項目は「〇〇」の赤いマスのままです。推測で埋めません。
- 病名を推測したり、診断や受診の要否、薬の判断に読める文は入れません。書類に書かれた病名や薬は書かれたとおりに写します。
- 費用と時間（架空データ、1人分の実測）: 1回 約 $0.39、93秒（Opus 5.5、入力 36,896 / 出力 11,990 トークン）。

## Claude Desktop から記録する（MCP、架空データの実演専用）

**この道具は既定で止まっています。** データベースごとの鍵のファイル（`data/demo.db` なら `data/demo.db.mcp_on`）が無ければ、Claude にもデータベースにも触らずに断ります。実在の利用者の話には使いません。架空データの実演の間だけ鍵を置き、終わったら取り除きます。

Claude Desktop に話した内容を、ケイカの入口と同じ整文と検査に通して記録します。検査に通らない話は記録にせず、入口の「聞くこと」に回します。

1. `uv pip install --python .venv/Scripts/python.exe -e ".[mcp]"` を実行します。
2. Claude Desktop を終了してから、設定ファイル `claude_desktop_config.json` の `mcpServers` に、次を足します。パスは自分の環境に合わせます。動いている間に足すと、終了の時に上書きされて消えました。

```json
{
  "mcpServers": {
    "keika": {
      "command": "C:/path/to/keika/.venv/Scripts/python.exe",
      "args": ["-m", "keika.cli", "mcp"],
      "env": {
        "KEIKA_DRIVE_ROOT": "C:/path/to/drive",
        "KEIKA_DB_PATH": "C:/path/to/keika/data/keika.db"
      }
    }
  }
}
```

3. Claude Desktop を起動し直し、「この話をケイカに記録して。柚木さん宅を訪問、変わりなし」のように話します。

- 同じ `KEIKA_DB_PATH` を画面でも使うと、記録が画面に出ます。先に `keika sync` で台帳を入れておきます。
- API キーはアプリのフォルダの `.env` を使います。
- Windows の Claude Desktop に登録して架空の話を1回入れ、記録になることを確かめました。空の話を記録しないことは、本物の MCP のやり取りで確かめました。
- Claude には話した言葉をそのまま渡すように頼んでいますが、言い換えないことを機械では保証できません。
- Claude Desktop に話した内容の扱いは、Claude のアプリの規約と設定によります。API の前提と同じとは限りません。

## 守っていること

- 話していない事実を足しません。話に無い数字や人名は機械で見つけ、自動で保存せず、入口の「聞くこと」に回します。
- 誰の話か AI が迷ったと申告した時は、自動で振り分けず「聞くこと」に回します。本人の名前の誤変換は、AI が台帳で直してそのまま記録することがあります。字違いがすべて止まるわけではなく、呼び方の報告の形によって確認に回る時と回らない時があります。元の文と記録はあとから見比べられます。
- 確認に回った記録は、AI の提案を1文で見せます。〔違う〕で人が書いた内容を AI が反映する時も、同じ検査を通し、話にも書いた内容にも無い言葉が入れば採用しません。薬の名前、分量、病名、受診の言葉は聞いて足す形にしません。
- すべての指摘に根拠の書類と箇所か、探した範囲が付きます。原文に無い引用は機械で落とします。文字の層が無いスキャンの引用は機械で照合できないので、その旨を画面に出します。
- 記録の下書きと指摘は AI（Claude）が作り、最終判断は人が行います。
- 薬の中止や変更、診断、受診の要否、緊急度の判定には踏み込みません。薬から病名を推測しません。
- 薬の名前と量は話のとおりに保存し、自動では直しません。怪しい薬名は、聞こえた言葉と、その利用者の書類や確定済みの記録の記載を並べて見せ、人が押した時だけ直します。どちらにも無ければ「薬の名前を確かめてください」とだけ出します。確認の結果は履歴に残ります。
- 整えた文章に話に無い薬名や病名、受診の判定が入ったら機械で止めて、人に回します。
- 記録は普通に直せます。直す前の内容はデータとして残り、アプリの中では消せません（画面には出しません）。データベースのファイルを直接触ることや、書類フォルダの書類の改変までは防げません。
- ログインや権限はありません。誰が直したかの名前は、利用者の申告です。事業所内のネットワークだけで使ってください。

## 測定の結果と費用

作り手側が作った架空データでの結果です。実地の精度ではありません。採点は、別の Claude が判定表と意味で照らしました。詳しい経緯は [docs/claude-usage.md](docs/claude-usage.md) にあります。

| 測定 | 指摘の穴 | 先回り | わなの誤り |
|---|---|---|---|
| 調整用データ、同じ条件で3回 | 17〜19 / 21 | 各 2 / 2 | 各 0 / 5 |
| 調整用データ、話を入れた後で1回 | 19 / 21 | 2 / 2 | 0 / 5 |
| 調整に使っていない確認用データ、1回 | 6 / 6 | 1 / 1（区分の一致まで求めると 0 / 1） | 0 / 5 |
| 見直しの周を足し、直した後の調整用データ、1回 | 21 / 21 | 2 / 2 | 0 / 5 |
| 調整に使っていない新しい確認用データ（5人）、1回 | 12 / 13 | 1 / 2（区分の一致まで） | 0 / 5 |

- 上の3行は見直しの周を足す前の結果です。穴の数は回によって2個ほど動きました。
- 21 / 21 は、見落としを確かめながら直した問題での1回の結果です。全部見つかるという意味ではありません。見ていないデータの 12 / 13 の方が実力に近い数字です。
- 判定表に無い指摘の中に、誤りが混じります（話を入れた後の回で9件中4件。うち2件はその後直しました）。指摘はそのまま信じず、確かめるためのお知らせとして使ってください。
- 確認用データは3人だけで、6 / 6 を「取りこぼしなし」とは言えません。

**費用の目安**（Claude の API の料金。測定の実費で、架空データの場合）

| 処理 | 実費 | 頻度 |
|---|---|---|
| 書類の読み取り（Opus 5.5、122通） | 約 $6.0 | 同じ書類は読み直さないので、初回だけ |
| 利用者の点検（8人） | 約 $2.4（1人あたり約 $0.3） | 点検のたび |
| 話した内容の整文（Opus 5.5、9件） | 約 $0.42（1件あたり約 $0.05） | 話すたび |

書類の量や話の長さで変わります。

## 事業所の実データで使う場合の注意

画面の下の「導入の前に」に、始める前に揃える3つと、同意書のたたき台（Word）があります。個人情報の考え方は、開始前に事業所で整理した知見を元に、期間中に書き起こしました。

この作品はハッカソンの提出物で、架空データだけで作って試しています。実データでの精度は測っていません。事業所で使うことを考える時は、次を踏まえて事業所の責任で判断してください。

- 病歴や心身の状況は、個人情報保護法の要配慮個人情報にあたり、特に慎重に扱う情報です。利用者や家族の同意と、事業所の管理のもとで扱ってください。
- **Claude の API に送るもの**: 話した内容、台帳の氏名と読み、読み取る書類の中身、支援経過の本文。送信先は Anthropic です。保存期間や学習への利用は、Anthropic の最新の規約と契約で確かめてください。
- **音声入力**: 主な入口は OS の音声入力です（Windows は Win + H、Mac はシステム設定の「キーボード」の「音声入力」）。送り先は OS と設定によります。Windows の音声入力はオンラインの音声認識（Azure Speech）を使うと Microsoft が説明しています。実データで使う時は、事業所で確認してください。
- **「話す（端末内）」のボタン**: ブラウザの端末内の認識（`processLocally`）が日本語で使える時だけ出ます。使えない時に、外部へ送る認識へは切り替えません。
- **手元に保存するもの**: `KEIKA_DB_PATH` の SQLite ファイルに、台帳、読み取り結果、支援経過と変更の履歴、話した元の文、指摘の結果が平文で入ります。ファイルの暗号化やログインの仕組みはありません。置き場所と権限の管理は事業所で行ってください。
- 書類はアプリが書き換えません。読むのは `KEIKA_DRIVE_ROOT` の中だけです。書き込むのは、押した時に下書きの Word を置く `ケイカの出力` だけです。
- 学習に使われない API での利用を前提にしています。自前の外部サーバーは持ちません。書類の読み取りでは中身を送りますが、読み取った後の日付の点検では送り直しません。
- 利用者の同意の文例（外国にある事業者への提供を含む）を [docs/consent-template.md](docs/consent-template.md) に置いています。たたき台なので、事業所で確かめて使ってください。
- 国内で処理したい事業所向けの選択肢（国内のクラウド経由など）は構想で、作っていません。
