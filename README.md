# ケイカ（仮称）

話すだけで支援経過。運営指導の備えは、そのついでに。

ケアマネジャーが話した内容を支援経過の文章に整え、事業所の Google ドライブにある書類と突き合わせて、確かめておきたいことを先回りで知らせるアプリです。Built with Claude: Japan 2026 の提出作品として制作中です。

> 指摘はすべて「確認してください」という形のお知らせです。法的助言や監査の代わりではなく、最終判断は事業所と保険者にあります。

## 触ってみる（API キー不要）

同梱の結果（架空データ）をそのまま見られます。Claude は呼びません。

```
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe -e ".[dev]"
.venv/Scripts/python.exe -m keika.cli serve --sample
```

http://127.0.0.1:8000 を開きます。

## 架空データで Claude を動かす

アプリのフォルダに `.env` というファイルを作り、`ANTHROPIC_API_KEY=自分のキー` の1行を書きます。`.env` はリポジトリに入りません。
書類のフォルダは `KEIKA_DRIVE_ROOT` で指定します（中に `利用者/`、`事業所/`、`入口/` を置きます）。指定しなければ同梱の架空データを読みます。データベースの場所は `KEIKA_DB_PATH` です。

```
.venv/Scripts/python.exe -m keika.cli sync     # 書類を読み取り、支援経過の CSV を取り込む
.venv/Scripts/python.exe -m keika.cli serve    # 画面を開き、入口のフォルダを見張る
```

`KEIKA_AS_OF=2026-11-04` を指定すると、画面に「デモ基準日」と出て、その日を今日として動きます。記入日時は常に実際の時計です。

## Claude Desktop から記録する（MCP）

Claude Desktop に話した内容を、ケイカの入口と同じ整文と検査に通して記録します。検査に通らない話は記録にせず、やることの「記録の確認」に回します。

1. `uv pip install --python .venv/Scripts/python.exe -e ".[mcp]"` を実行します。
2. Claude Desktop の設定ファイル `claude_desktop_config.json` の `mcpServers` に、次を足します。パスは自分の環境に合わせます。

```json
{
  "mcpServers": {
    "keika": {
      "command": "C:/path/to/keika/.venv/Scripts/python.exe",
      "args": ["-m", "keika.cli", "mcp"],
      "env": {
        "KEIKA_DRIVE_ROOT": "C:/path/to/drive",
        "KEIKA_DB_PATH": "C:/path/to/keika/data/keika.db"
      }
    }
  }
}
```

3. Claude Desktop を起動し直し、「この話をケイカに記録して。柚木さん宅を訪問、変わりなし」のように話します。

- 同じ `KEIKA_DB_PATH` を画面でも使うと、記録が画面に出ます。先に `keika sync` で台帳を入れておきます。
- API キーはアプリのフォルダの `.env` を使います。
- 本物の MCP のやり取りと本物の Claude で、記録になること、空の話を記録しないことは確かめました。Claude Desktop に登録して実際に話す確認は、まだです。
- Claude には話した言葉をそのまま渡すように頼んでいますが、言い換えないことを機械では保証できません。
- Claude Desktop に話した内容の扱いは、Claude のアプリの規約と設定によります。API の前提と同じとは限りません。

## 守っていること

- 話していない事実を足しません。話に無い数字や人名は機械で見つけ、自動で保存せず、やることの「記録の確認」に回します。
- 誰の話か迷ったら、自動で振り分けず同じく「記録の確認」に回します。
- すべての指摘に根拠の書類と箇所か、探した範囲が付きます。原文に無い引用は機械で落とします。文字の層が無いスキャンの引用は機械で照合できないので、その旨を画面に出します。
- 記録の下書きと指摘は AI（Claude）が作り、最終判断は人が行います。
- 薬の中止や変更、診断、受診の要否、緊急度の判定には踏み込みません。薬から病名を推測しません。
- 薬の名前と量は話のとおりに保存し、自動では直しません。怪しい薬名は、聞こえた言葉と、その利用者の書類や確定済みの記録の記載を並べて見せ、人が押した時だけ直します。どちらにも無ければ「薬の名前を確かめてください」とだけ出します。確認の結果は履歴に残ります。
- 整えた文章に話に無い薬名や病名、受診の判定が入ったら機械で止めて、人に回します。
- 記録は普通に直せて、変更の履歴はアプリの中で消せません。データベースのファイルを直接触ることや、Drive の書類の改変までは防げません。
- ログインや権限はありません。誰が直したかの名前は、利用者の申告です。事業所内のネットワークだけで使ってください。

## 測定の結果と費用

作り手側が作った架空データでの結果です。実地の精度ではありません。採点は、別の Claude が判定表と意味で照らしました。詳しい経緯は [docs/claude-usage.md](docs/claude-usage.md) にあります。

| 測定 | 指摘の穴 | 先回り | わなの誤り |
|---|---|---|---|
| 調整用データ、同じ条件で3回 | 17〜19 / 21 | 各 2 / 2 | 各 0 / 5 |
| 調整用データ、話を入れた後で1回 | 19 / 21 | 2 / 2 | 0 / 5 |
| 調整に使っていない確認用データ、1回 | 6 / 6 | 1 / 1（区分の一致まで求めると 0 / 1） | 0 / 5 |

- 穴の数は回によって2個ほど動きます。3回とも見つからない穴もあります。
- 判定表に無い指摘の中に、誤りが混じります（話を入れた後の回で9件中4件。うち2件はその後直しました）。指摘はそのまま信じず、確かめるためのお知らせとして使ってください。
- 確認用データは3人だけで、6 / 6 を「取りこぼしなし」とは言えません。

**費用の目安**（Claude の API の料金。測定の実費で、架空データの場合）

| 処理 | 実費 | 頻度 |
|---|---|---|
| 書類の読み取り（Opus 5.5、122通） | 約 $6.0 | 同じ書類は読み直さないので、初回だけ |
| 利用者の点検（8人） | 約 $2.4（1人あたり約 $0.3） | 点検のたび |
| 話した内容の整文（Opus 5.5、9件） | 約 $0.42（1件あたり約 $0.05） | 話すたび |

書類の量や話の長さで変わります。

## データについて

`sample_data/` と `eval/answer_key.csv` はキックオフ前に作った架空の入力データです。実在の人物・事業所とは関係ありません。詳しくは [sample_data/README.md](sample_data/README.md) を見てください。

## 事業所の実データで使う場合の注意

この作品はハッカソンの提出物で、架空データだけで作って試しています。実データでの精度は測っていません。事業所で使うことを考える時は、次を踏まえて事業所の責任で判断してください。

- 病歴や心身の状況は、個人情報保護法の要配慮個人情報にあたり、特に慎重に扱う情報です。利用者や家族の同意と、事業所の管理のもとで扱ってください。
- **Claude の API に送るもの**: 話した内容、台帳の氏名と読み、読み取る書類の中身、支援経過の本文。送信先は Anthropic です。保存期間や学習への利用は、Anthropic の最新の規約と契約で確かめてください。
- **音声入力**: 主な入口は OS の音声入力です（Windows は Win + H、Mac はシステム設定の「キーボード」の「音声入力」）。送り先は OS と設定によります。Windows の音声入力はオンラインの音声認識（Azure Speech）を使うと Microsoft が説明しています。実データで使う時は、事業所で確認してください。
- **「話す（端末内）」のボタン**: ブラウザの端末内の認識（`processLocally`）が日本語で使える時だけ出ます。使えない時に、外部へ送る認識へは切り替えません。
- **手元に保存するもの**: `KEIKA_DB_PATH` の SQLite ファイルに、台帳、読み取り結果、支援経過と変更の履歴、話した元の文、指摘の結果が平文で入ります。ファイルの暗号化やログインの仕組みはありません。置き場所と権限の管理は事業所で行ってください。
- 書類はアプリが書き換えません。読むのは `KEIKA_DRIVE_ROOT` の中だけです。
- 学習に使われない API での利用を前提にしています。自前の外部サーバーは持ちません。書類の読み取りでは中身を送りますが、読み取った後の日付の点検では送り直しません。
- 利用者の同意の文例（外国にある事業者への提供を含む）を [docs/consent-template.md](docs/consent-template.md) に置いています。たたき台なので、事業所で確かめて使ってください。
- 国内で処理したい事業所向けの選択肢（国内のクラウド経由など）は構想で、作っていません。
